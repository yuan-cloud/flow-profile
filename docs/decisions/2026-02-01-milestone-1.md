# Risk Assessment: M1 Completion (Deterministic Bundle Pipeline)

Date: 2026-02-01
Milestone: M1 - Deterministic Bundle Pipeline

## Assumption Check
- Assumed Node-RED flow exports always include stable `id` fields and standard node shapes.
- Assumed the default redaction threshold (entropy 4.5) is broadly acceptable without per-user tuning.
- Assumed support bundle outputs are sufficient without extra metadata for tooling integration.

## Counter-Argument
- A skeptical engineer could argue the CLI should avoid generating ZIP bundles until streaming is supported to reduce memory pressure on large flows.
- Another alternative is to expose a structured JSON schema for outputs instead of relying on human-readable markdown where possible.

## Risk Scenario
- Production risk: Large flows could trigger high memory usage during bundle creation, causing slowdowns or crashes.
  - Detection: CI performance regression, user reports of timeouts, runtime memory spikes.
  - Blast radius: Affects single user runs, potentially causing CLI failures for large flows.

## Questions to Reconsider
- Should redaction thresholds be user-configurable with documented defaults and warnings?
- Do we need schema validation for outputs to ensure compatibility with downstream tooling?
- Should we add streaming or chunked output support for the bundle zip?

## Tech Debt Flags
- Hard-coded output formats and thresholds may be costly to change later.
- CLI integration tests currently depend on workspace package entry resolution; this could mask real failures.

## Rollback Plan
- The support-bundle ZIP can be removed while keeping JSON/markdown outputs intact.
- The CLI can be decoupled from web UI entirely; core outputs remain usable as a library.
